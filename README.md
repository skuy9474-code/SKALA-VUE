# 오늘의 OOTD 날씨 코치

Vue 수업에서 배운 문법부터 Component, Router, Pinia, Axios까지 하나의 날씨 서비스에 순서대로 적용한 프로젝트입니다.

처음에는 도시별 날씨를 보여주는 간단한 화면으로 시작했습니다. 이후 실제 날씨 API를 연결하고, 확인한 날씨에 맞춰 옷차림과 헤어스타일, 신발, 준비물을 추천하는 `오늘의 OOTD 날씨 코치`로 확장했습니다.

## 실행 방법

```bash
npm install
npm run dev
```

개발 서버가 실행되면 터미널에 표시된 주소로 접속합니다. 기본 주소는 `http://localhost:5173`입니다.

제출 전 확인 명령어는 다음과 같습니다.

```bash
npm run lint
npm run build
```

## 과제 구현 내용

### 과제 1. Weather Mockup

- 도시 데이터를 배열로 만들고 `v-for`와 `:key`를 사용해 날씨 카드를 반복 출력했습니다.
- 온도에 따라 더움과 선선함을 나누면서 `v-if`, `v-else`를 연습했습니다.
- 한글 도시 검색에는 `:value`와 `@input`을 사용했습니다.
- 카드 안의 상세보기 버튼에는 `@click.stop`을 적용해 이벤트 버블링을 막았습니다.
- 수업에서 제공한 데이터에 제주 지역을 직접 추가했습니다.

### 과제 2. Weather Composition

- 검색어와 선택 문구, 기준 온도를 `ref`로 관리했습니다.
- 검색 결과와 평균 기온처럼 기존 값으로 계산할 수 있는 내용은 `computed`로 작성했습니다.
- 선택 문구와 기준 온도는 `watch`, 검색어는 `watchEffect`로 변화를 확인했습니다.

### 과제 3. Weather Component

- `WeatherParent`가 날씨 데이터와 기능을 관리하도록 역할을 나눴습니다.
- `SearchBar`와 `WeatherCard`는 Props로 데이터를 받고, 입력과 클릭 결과는 Emits로 부모에게 전달합니다.
- 공통 카드 틀인 `BaseDashboardCard`에는 Slot을 사용했습니다.
- 수업 요구사항 외에 지역을 입력할 수 있는 `CityAddForm`도 추가했습니다.

### 과제 4. Vue Router

- 한 화면에 있던 기능을 메인, 상세, 소개 화면으로 나눴습니다.
- `/weather/:cityId`에서 동적 경로를 사용했습니다.
- 상세보기 버튼을 누르면 `router.push()`로 이동합니다.
- 잘못된 주소는 Catch-all Route로 처리했습니다.

### 과제 5. Pinia

- `configStore`에서 섭씨와 화씨 단위를 공통으로 관리합니다.
- 메인 화면과 상세 화면에서 같은 온도 단위를 사용합니다.
- 추가 State로 단위 변경 횟수를 저장했습니다.
- 추가 Getter로 현재 단위의 한글 이름을 만들었습니다.
- 추가 Action으로 단위 설정을 초기화할 수 있게 했습니다.

### 과제 6. Axios

- OpenWeather에서 현재 날씨를 받아 Mock 데이터를 실제 데이터로 교체했습니다.
- 같은 지역의 좌표를 이용해 OpenWeather 대기질 정보도 함께 조회했습니다.
- JSONPlaceholder API로 GET, POST, PUT, DELETE를 연습했습니다.
- API 키가 없으면 Mock 날씨가 계속 보이도록 했습니다.

### Code Challenge. UI Library

- Element Plus를 전역으로 등록했습니다.
- `el-card`, `el-input`, `el-switch`, `el-button`으로 회원가입 화면을 만들었습니다.
- `el-input-number`, `el-rate`로 상품 수량과 별점을 변경합니다.
- `ElMessageBox`와 `el-progress`로 삭제 확인과 진행률을 구현했습니다.

### Hands on. Weather UI Library

- 기존 날씨 화면에 Element Plus의 입력창, 선택창, 버튼, 메시지, 대화상자를 적용했습니다.
- OpenWeather의 현재 날씨·대기질과 Open-Meteo의 자외선 지수를 OOTD 추천에 사용했습니다.
- 남자·여자를 선택하고 기온에 맞는 옷차림과 신발을 추천합니다.
- 선택한 성별과 습도·바람에 맞는 헤어스타일을 추천합니다.
- 자외선 지수에 따라 선크림, 선글라스, 모자 등을 안내합니다.
- 인천·대전·대구·광주·강릉·춘천·전주를 선택해 날씨 카드에 추가하거나 삭제할 수 있습니다.
- 지역 카드를 클릭하면 선택 지역 배너가 나타나고, 맑음·흐림·비·눈·바람에 따라 배경 사진이 바뀝니다.

### Code Challenge. Vite Build

- ESLint에 `eqeqeq`와 `no-console` 규칙을 설정했습니다.
- Prettier를 실행하여 실습 코드를 정렬했습니다.
- staging과 production 환경별 `VITE_API_URL`을 분리했습니다.
- `npm run build:staging`과 `npm run build:production` 스크립트를 추가했습니다.

## API 키 설정

날씨 데이터는 제가 발급받은 OpenWeather API 키로 불러왔습니다. 실제 키는 코드에 직접 넣지 않고 `.env.local` 파일에 아래와 같이 저장했습니다.

```env
VITE_OPENWEATHER_API_KEY=본인_API_KEY
VITE_UNSPLASH_ACCESS_KEY=본인_UNSPLASH_ACCESS_KEY
```

OpenWeather 키는 날씨와 대기질을 가져올 때 사용하고, Unsplash 키는 OOTD 참고 사진을 검색할 때 사용합니다. 처음에는 키를 입력하고도 Mock 데이터가 계속 나왔는데, 개발 서버를 껐다가 다시 실행하니 적용되었습니다. `.env.local`은 Git에 올라가지 않도록 제외했고, 다른 사람이 설정 방법을 알 수 있도록 `.env.example`에는 변수 이름만 남겨 두었습니다. 자외선 정보를 가져오는 Open-Meteo는 별도의 키가 필요하지 않았습니다.

## Troubleshooting

### API 키를 넣었는데도 Mock 데이터가 표시된 문제

- **문제 상황:** 새로 발급받은 OpenWeather API 키를 `.env.local`에 입력했는데도 실제 날씨가 나오지 않고 Mock 데이터가 계속 표시되었습니다.
- **원인:** Vite는 개발 서버를 실행할 때 환경변수를 읽기 때문에, 서버가 실행 중인 상태에서 API 키를 입력해도 바로 반영되지 않았습니다. 또한 환경변수 이름이 `VITE_`로 시작해야 Vue 코드에서 읽을 수 있다는 점도 확인했습니다.
- **해결 결과:** 환경변수 이름을 `VITE_OPENWEATHER_API_KEY`로 작성하고 개발 서버를 종료한 뒤 `npm run dev`로 다시 실행했습니다. 재실행 후에는 입력한 키로 OpenWeather API를 호출할 수 있었습니다.

### 날씨는 나오는데 자외선 정보만 갱신되지 않은 문제

- **문제 상황:** OpenWeather에서 날씨 정보는 정상적으로 받아왔지만 자외선 값은 실시간으로 바뀌지 않았습니다.
- **원인:** 자외선 정보를 요청하는 Open-Meteo API가 짧은 시간에 여러 지역의 데이터를 요청하면서 `HTTP 429` 응답을 반환했습니다. 이는 코드 문법 문제가 아니라 API 요청 한도 때문에 발생한 문제였습니다.
- **해결 결과:** 자외선 API 호출에 실패해도 전체 화면이 멈추지 않도록 기존 값을 보여 주는 예외 처리를 적용했습니다. 요청 한도가 정상화되면 다시 실시간 자외선 값을 표시하도록 구성했습니다.

### 상세 화면에서 일출과 일몰이 보이지 않은 문제

- **문제 상황:** 날씨 상세 화면에 일출과 일몰 영역을 만들었지만 값이 `-`로 표시되었습니다.
- **원인:** 화면만 먼저 만들고 OpenWeather 응답에 포함된 `sys.sunrise`, `sys.sunset` 값을 상세 화면에서 사용할 데이터로 연결하지 않았기 때문입니다. API에서 받은 시간은 그대로 표시할 수 있는 문자열이 아니라 Unix 시간 형식이라는 점도 원인이었습니다.
- **해결 결과:** 두 값을 날씨 데이터에 포함하고, 사용자가 선택한 지역의 시간대에 맞는 시각으로 변환했습니다. 이후 상세 화면에서 일출과 일몰 시간을 확인할 수 있었습니다.

### 새로 추가한 지역의 상세 날씨를 찾지 못한 문제

- **문제 상황:** 기본으로 제공한 지역은 상세 화면이 열렸지만, 사용자가 직접 추가한 지역은 상세 화면에서 지역 정보를 찾지 못하는 경우가 있었습니다.
- **원인:** 상세 화면은 `cityId`로 지역을 찾는데, 새로 추가한 지역은 미리 작성된 기본 지역 목록에 없어서 이름과 API 검색에 사용할 영문명이 전달되지 않았습니다.
- **해결 결과:** 상세 화면으로 이동할 때 동적 경로의 `cityId`와 함께 지역 이름과 검색명을 Query로 전달했습니다. 그 결과 사용자가 추가한 지역도 같은 상세 화면을 재사용할 수 있게 되었습니다.

### 지역별 API 호출 때문에 카드 표시가 늦어진 문제

- **문제 상황:** 여러 지역을 등록한 뒤 처음 접속하면 지역 카드가 한 번에 표시되지 않고 잠시 늦게 나타났습니다.
- **원인:** 각 지역마다 현재 날씨와 대기질, 자외선 정보를 각각 요청하기 때문에 등록한 지역이 많아질수록 외부 API 응답을 기다리는 시간이 늘어났습니다.
- **해결 결과:** 데이터를 불러오는 동안 로딩 상태를 표시하고, 일부 부가 정보 호출에 실패해도 받아온 날씨 정보부터 화면에 표시하도록 처리했습니다. 사용자가 필요할 때 다시 요청할 수 있도록 새로고침 기능도 유지했습니다.

### OOTD 추천과 스타일 사진이 잘 맞지 않은 문제

- **문제 상황:** 처음에는 Unsplash에서 불러온 사진이 오늘의 옷 추천과 잘 맞지 않거나, 검색 결과가 하나뿐이라 한 가지 코디만 보이는 경우가 있었습니다.
- **원인:** 검색어가 너무 넓으면 옷과 관계없는 사진이 나왔고, 반대로 기온과 옷 종류까지 너무 구체적으로 작성하면 검색되는 사진 수가 부족했습니다.
- **해결 결과:** 성별과 날씨, 기온에 맞는 검색어로 사진을 요청한 뒤 옷 관련 단어와 전신 사진 여부를 비교해 잘 맞는 사진을 골랐습니다. 결과가 3장보다 적을 때는 같은 성별과 계절의 검색 결과로 부족한 사진을 채워, 서로 다른 코디 3개를 비교할 수 있게 했습니다.

### 빌드 중 큰 파일 경고가 표시된 문제

- **문제 상황:** `npm run build`를 실행했을 때 `Some chunks are larger than 500 kB`라는 문구가 나와서 빌드가 실패한 것으로 생각했습니다.
- **원인:** Element Plus와 같은 라이브러리가 포함되면서 JavaScript 파일의 크기가 권장 크기보다 커졌다는 안내였습니다. 실제 오류가 아니라 최적화와 관련된 경고였습니다.
- **해결 결과:** 터미널 마지막에 `built`가 출력되고 `dist` 폴더가 정상적으로 생성되는 것을 확인해 빌드가 완료되었다고 판단했습니다. 이후 `npm run lint`도 함께 실행해 코드 오류가 없는지 확인했습니다.

## 과제를 하면서 알게 된 점

- `ref`와 `computed`가 처음에는 제일 헷갈렸다. 검색어처럼 직접 바뀌는 값은 `ref`, 검색 결과처럼 그 값을 따라가는 내용은 `computed`로 나누니 차이가 보였다.
- 날씨 카드를 컴포넌트로 나누면서 Props는 부모가 자식에게 값을 줄 때 쓰고, Emits는 카드 클릭처럼 자식에서 일어난 일을 부모에게 알려줄 때 쓴다는 것을 알게 되었습니다. 날씨 배열은 부모가 관리하고 카드는 받은 내용을 보여 주도록 역할을 나눴습니다.
- 상세 페이지는 지역마다 따로 만들 필요가 없었습니다. `/weather/:cityId`에서 `cityId`만 바꾸면 같은 화면으로 다른 지역을 보여 줄 수 있었습니다. 사용자가 추가한 지역은 이름도 같이 필요해서 Query로 넘겼습니다.
- 섭씨와 화씨는 메인 화면과 상세 화면에서 같이 바뀌어야 해서 Pinia에 저장했습니다. 한 화면에서 단위를 바꿨을 때 다른 화면에도 그대로 적용되는 것을 확인하면서 공통 상태를 왜 Store에 두는지 이해했습니다.
- 실제 API를 붙이면서 요청이 항상 성공하는 것은 아니라는 점을 알게 되었습니다. 날씨 요청이 실패했을 때는 Mock 데이터를 보여 주고, 자외선 요청만 실패하면 나머지 날씨 정보는 그대로 보이도록 나눠서 처리했습니다.
- API 키를 코드에 바로 적으면 GitHub에 같이 올라갈 수 있기 때문에 `.env.local`에 따로 저장했습니다. 키를 입력한 뒤 서버를 다시 실행해야 적용된다는 것도 직접 확인했습니다.
- Unsplash는 검색어를 너무 구체적으로 쓰니 사진이 하나만 나오기도 했다. 먼저 조건에 맞는 사진을 찾고, 부족한 수는 같은 성별과 계절의 검색 결과로 채우도록 바꾸었다.
